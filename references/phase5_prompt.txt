# 2. Phase objective

Implement the **Python analytics/data-processing layer** that consumes the PostgreSQL analytical SQL outputs and prepares clean datasets for the eventual Streamlit dashboard.

The objective is:

```text id="1x0m0v"
PostgreSQL
    ↓
analytical SQL
    ↓
Python
    ↓
pandas DataFrames
    ↓
dashboard-ready analytical datasets
```

This phase should demonstrate practical Python analytics skills while preserving the SQL layer as the primary analytical source.

The Python layer must NOT become a second, conflicting analytics engine.

---

# 3. Critical architecture rule

Prefer:

> **SQL for database-intensive aggregation and relational analytics.**

Use Python/pandas for:

* retrieving SQL results
* light transformation
* reshaping
* dashboard preparation
* plotting-oriented data preparation
* presentation-friendly calculations
* combining already-computed analytical datasets where appropriate

Do NOT unnecessarily pull the entire 245,210-row transaction table into pandas and redo all SQL analytics there.

The project should demonstrate an appropriate division of responsibilities:

```text id="yj8u6k"
PostgreSQL:
joins
aggregations
RFM
cohorts
revenue concentration
category analysis

Python:
retrieval
validation
light transformation
dashboard datasets
visualization preparation
```

This distinction is important for both technical correctness and the Xeno role.

# 16. Data validation

Implement Python-side validation of the analytical datasets.

This validation should complement, not replace, the PostgreSQL validation already performed in Phase 3.

At minimum validate:

### KPI consistency

```text id="5r3i2r"
total revenue == 53,581,128.12
transactions == 245,210
```

Use actual database-derived values rather than hard-coding assumptions where practical.

### Customer revenue conservation

Sum of customer revenue should reconcile with total revenue.

### Category revenue conservation

Sum of category revenue should reconcile with total revenue.

### RFM coverage

RFM customer counts should cover all active customers.

### Cohort integrity

Retention counts/rates must be within logical bounds.

### Concentration monotonicity

Cumulative revenue share should not decrease as customer coverage increases.

### Top-customer ordering

Top customers should be ordered consistently by total revenue.
