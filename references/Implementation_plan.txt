4. Generate realistic customer behavior

This is important.

Don't do:

np.random.randint(...)

for everything.

Create customer behavioral archetypes.

For example:

Champions
    high frequency
    high monetary value
    recent purchases

Loyal
    medium/high frequency
    consistent purchases

New
    recent signup
    low transaction count

At Risk
    historically valuable
    long time since last purchase

Lost
    long inactivity period
    historically active

The generator should produce distributions that naturally create these groups.

For example:

customer
   │
   ├── propensity_to_purchase
   ├── average_order_value
   ├── preferred_category
   ├── purchase_frequency
   └── inactivity_probability

Then transactions are sampled based on those latent characteristics.

This makes your analytics results much more meaningful.

17. Caching strategy

You specifically asked for caching.

There are two different kinds of caching here.

Application caching

Use Streamlit's caching mechanisms.

Conceptually:

@st.cache_data
def get_revenue_data(...):
    ...

This avoids repeatedly executing expensive analytical queries.

For database connections, use the appropriate resource-level cache.

Agent context caching

This is separate.

Don't store huge transcripts.

Instead maintain compact state files.
